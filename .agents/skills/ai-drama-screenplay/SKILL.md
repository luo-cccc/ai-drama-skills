# AI Drama Screenplay

把成熟叙事转成可追溯、可确认、可拍摄并能被审计和分镜稳定引用的剧本产物。以来源文本、用户明确约束和已确认上游为优先依据。

## 选择任务支线

先识别用户真正要求的最小范围，不强制跑完整流程：

| 支线 | 最小输入 | 执行范围 |
|:--|:--|:--|
| 形态建议 | 成熟故事或大纲 | 形态判断 |
| 提示包 | 成熟故事或大纲 | 形态判断（如未定）→ 提示包 |
| 分场 | 故事 + 已确认提示包，或用户授权最小护栏包 | 提示包 → 分场 |
| 标准剧本 | 成熟故事或已确认开发方案 | 形态 → 提示包 → 分场 → 正文 |
| 续写或修订 | 目标剧本版本 + 上游基准 + 修改目标 | 核对基准 → 修改指定范围 |

只有概念、没有可确定故事骨架时，转交 `ai-drama-development`。用户要求完整小说改短剧系列、全流程短剧或 `ai-short-drama-series` 项目时，转交 `ai-drama-short-drama`；不得因消息里出现“剧本”就隐式抢路由。已有剧本只需评估或证据审计时，转交 `ai-drama-script-audit`。不要在本技能生成分镜、资产图、演员读本或导演阐述。

## 读取参考

- 判断媒介形态或生成提示包时，读取 [form-and-brief.md](references/form-and-brief.md)。
- 生成、修订或校验分场和正文时，读取 [outline-and-screenplay.md](references/outline-and-screenplay.md)。
- 进入项目模式时读取 [workflow-contract.md](references/workflow-contract.md)；写正式正文时读取 [screenplay-format.md](references/screenplay-format.md)。
- 涉及第三方素材时读取 [originality-safety.md](references/originality-safety.md)；设计可见表演时按需读取 [performance-camera.md](references/performance-camera.md)。

## 验证输入

1. 读取完整指定范围，记录来源、版本和用户约束。
2. 检查主角、目标或冲突、关键关系、结局方向和基调，不使用字数门槛。
3. 信息完整即可继续；缺失次要信息时写明最小假设。
4. 缺失项会改变人物关系、结局或作品形态时暂停，只请求决定性信息。
5. 不提供来源文本时，可以按现有提示包或大纲工作，但必须写明“无法独立验证来源忠实度”。

## 执行阶段

使用稳定阶段名，不使用 Step 编号：

`intake -> brief -> outline -> screenplay`

### intake：判断形态

给出一个主推荐、推荐强度、具体理由、制作与叙事代价。不要用“都可以”回避判断。用户坚持非推荐形态时尊重选择，把代价写入提示包。

### brief：建立控制层

生成完整提示包。用户要求跳过时仍生成最小护栏包，至少包含来源优先级、不可改核心、禁止行为、格式规则和自检标准；记录授权与风险。

### outline：固定逐场承诺

按引用中的字段生成分场。只写编剧结构，不提前加入镜号、景别、机位、灯光或导演调度。发现分场与提示包冲突时先重写分场。

### screenplay：生成可拍正文

只消费已确认提示包与分场。让每个场号稳定可引用；把不可见心理转为可见动作、停顿、物件、空间反应或明确的主观画面。不要无依据新增关系、动机、极端事件、关键台词或结局。

长剧本按 3–8 场或约 3000–6000 字分批；标记已完成范围、当前状态和下一批起点，不用压缩质量换取一次性输出。

## 执行检查点

| 检查点 | 默认行为 | 可继续依据 |
|:--|:--|:--|
| 方向 | 形态或故事方向未确认时暂停 | 用户已指定，或预授权专业判断 |
| 提示包 | 新建或实质修订后暂停 | 用户确认版本，或预授权连续执行 |
| 分场 | 新建或实质修订后暂停 | 用户确认版本，或预授权连续执行 |
| 剧本 | 每一稿与审计结果一并交付后暂停 | 用户确认具体版本，或该版本处于明确预授权范围且通过预设验收 |

不要把“每一步都暂停”当成规则。用户预授权时连续执行，并在项目模式记录授权范围、时间和依据。只有明确写出阶段或版本范围、允许自动确认以及验收条件的预授权，才能在审计通过后把对应版本设为 `confirmed`；泛化的“继续做”不能替代具体版本确认。未经确认的剧本不得作为正式分镜或锁定资产的基准。

## 处理项目与版本

- 向上查找 `project-state.json`。找到时运行项目模式，读取已确认上游、登记依赖和检查点，并更新当前阶段。
- 未找到时运行独立模式，不强制建项目，也不声称跨批次连续。
- 使用 `prompt-pack-vNNN.md`、`scene-outline-vNNN.md`、`screenplay-vNNN.md` 等稳定英文文件名；版本从 `v001` 递增，不覆盖旧稿。
- 给正式产物记录来源版本、状态和变更摘要。使用 `draft`、`pending-confirmation`、`confirmed`、`superseded` 或 `invalid`。
- 每一稿完成后调用 `ai-drama-script-audit` 生成独立审计报告；审计无效或存在阻断项时，不请求确认进入下游。

## 回退与完成检查

- 形态改变时回到 `brief`，更新结构、体量和改编代价。
- 分场违反提示包时标出冲突场并重写，不进入正文。
- 正文偏离确认分场时停止续写，先给逐场差异；需要改分场时重新确认。
- 上游未知时保持待确认，不用完整表格掩盖缺失事实。
- 确认所有普通场保持单一连续时空，多空间只使用显式“连续场组”或“交叉剪辑”；连续场标题只使用 ASCII `->`。
- 确认对白、动作、屏幕文字和主观画面符合精确格式，指代清楚且可拍摄。
- 确认必保场景、台词、物件和母题均可由场号或短引检索。
