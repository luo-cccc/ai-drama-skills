# 证据、符合性与修订门禁

## Canonical Audit JSON

v2 正式审计是完整的 `audit-report.schema.json` 实例，至少包含精确 scope、目标 artifact/path/hash、审计依据、findings、required elements、differences、decision 和 limitations。每个 required element 的通过结论必须有证据，每个 finding 必须有 evidence、judgment、impact、action 和 acceptance condition。

`project-state.json` 中的 `audit_result` 是由 canonical report 派生的六键摘要：`p0_count`、`p1_count`、`p2_count`、`required_elements_total`、`required_elements_passed`、`decision`。禁止手填或让摘要与报告数组不一致。Markdown 仅为派生展示；v1/独立兼容报告可嵌入六键 `ai-drama-audit` marker，但不能作为 v2 放行依据。

机器结构门验证 Schema、计数、证据定位、覆盖和决策一致性；创意复核另行判断因果、人物、节奏、对白、可拍性与制作风险。

## 证据单位

每个关键问题使用：

- `【证据】`：集数、场号、段落、检索结果或最短必要原文短引；
- `【判断】`：说明结构、人物、场景、可拍性、对白或格式发生了什么；
- `【影响】`：说明对理解、因果、节奏、情绪、连续性或制作的实际影响；
- `【修正方向】`：给出可执行动作；
- `【验收标准】`：说明修改后如何重新检索或判断。

每个“通过”至少附一个证据位置。找不到必须元素时写明检索范围和“0 次”。允许等效改写的元素说明功能等价依据。引用只截取支持判断的最短片段。

## 符合性核对

按优先级核对：来源和用户约束 → 已确认提示包 → 已确认分场 → 当前剧本。

### 必保元素证据表

| 约束 | 来源 | 要求 | 正文证据 | 结果 |
|:--|:--|:--|:--|:--|
| 场景/台词/动作/物件/母题 | 文件、章节或短引 | 原样/等效/不得删除 | 场号 + 短引或 0 次 | 通过/问题/无法验证 |

### 分场到正文差异表

| 场号 | 分场基准 | 正文实现 | 授权或变更记录 | 结果 |
|:--|:--|:--|:--|:--|

逐场核对空间、人物、戏剧任务、核心事件、必保元素、转折和场尾。连续且完全一致的场次可以合并报告范围；任何差异都逐场列出。没有授权的结构差异不能标为通过。

同时检查：

- 人物关系、结局、关键动机和价值判断没有偏离；
- 没有无依据新增极端冲突或删除伏笔回收；
- 所有普通场保持单一连续时空，多空间类型正确标记；
- 场标题、人物名单独加粗、对白换行和屏幕文字格式一致；
- 不可见心理已转为可拍内容，主观画面有明确起止；
- 分镜、导演说明和审计文字没有混入纯剧本正文。

## 优先级

- `P0 阻断`：违反不可改核心、核心因果断裂、人物关系或结局跑偏、世界规则矛盾、高潮无法成立、确认分场发生未授权实质漂移。
- `P1 主要`：必保场景或元素遗漏、人物动机跳跃、场景功能重复、节奏明显失衡、冲突升级不足、严重格式或可拍性问题、台词持续说破潜台词。
- `P2 优化`：局部节奏、措辞、微表演、镜头机会、动作精度或非阻断格式细节。

每项使用可机器计数的标题和证据体：

`### [P0] 问题短名`、`### [P1] 问题短名` 或 `### [P2] 问题短名`，其下写 `位置｜证据｜影响｜建议动作｜验收标准`。不要在其他标题或自由文本里声明不同的严重度数量。

## 版本对比

二稿及以后分别列出：

1. 已解决：引用上一稿问题和本稿证据；
2. 未解决：说明问题为何仍成立；
3. 新增问题：证明由本稿改变引入；
4. 净变化：总结结构、人物、场景、台词和可拍性是否实质改善。

不要因措辞变化就宣称问题已解决。修订必须满足上一稿验收标准。

## 门禁结论

| 条件 | 结论 |
|:--|:--|
| 任一 P0 | 必须下一稿；禁止正式分镜和锁定资产 |
| P1 达到 3 项或以上 | 建议下一稿；用户拒绝时记录风险与授权 |
| 仅 P2 | 可建议确认当前版本并进入下游 |
| 关键上游缺失 | 只对可验证范围下结论，不给完整符合性通过 |
| 证据不存在或报告与正文矛盾 | 报告无效，重新审计 |

门禁只判断是否具备请求用户确认或进入下游的条件，不代替用户确认具体剧本版本。

## 修订轮次

按顺序处理并在每轮后复核因果：

1. 结构轮：目标、因果、节拍、规则和高潮；
2. 人物轮：选择、策略、代价、关系和弧光；
3. 场景轮：进入、目标、转折、退出和重复功能；
4. 台词轮：语言肖像、潜台词、信息权限和对抗策略；
5. 视觉轮：可见动作、空间、物件、声音和光影。

定向修订只处理用户批准范围。任何改动触及已确认分场的空间、核心事件、必保元素或场尾时，先回退分场确认。
